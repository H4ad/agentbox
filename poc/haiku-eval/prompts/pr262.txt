Bug: removing a project fails with `constraint failed: FOREIGN KEY constraint failed (787)`. `agent_seq.project` references `projects(name)` and `Store.RemoveProject` (internal/state/state.go) never deletes that row, so any project that ever had an agent can't be removed. Also, every other table keyed by a project is left behind, so a project added again under the same name inherits it.

Fix: make `RemoveProject` run in one transaction: count agents (still refuse while any exist), delete every row keyed by the project from the tables in a package var `projectOwned []string`, delete the project, renumber the project list, commit. Find the tables from the schema (migrations in state.go: every table with a `project` column or a foreign key to projects). Delete with the project: agent_seq, pr_watches, agent_queue, agent_events, checkpoints, questions, notifications, running_turns, chat_items, chats, secrets, connectors, connector_projects, skill_projects, and project memory (memory_serves, memory_anchors, memory_duplicates, consolidation_passes, working_memory, memories, agent_reports, artifacts, events). Keep as history, listed in a package var `projectKept map[string]string` (table -> why): agents (blocks removal), media (files on disk, swept by retention), token_usage (spend history). Fold the old separate secrets/connectors/skill_projects deletes into the transaction.

Add tests in internal/state: one that makes an agent in two projects with secrets, chat and media, destroys it, removes one project, and checks its owned rows are gone, the other project's intact, media kept, and numbering restarts at agent-01; and one that walks sqlite_master and fails if a table with a `project` column or a foreign key to projects is in neither projectOwned nor projectKept. Run `go test ./internal/state` and `go vet ./internal/state`. Do not push.
